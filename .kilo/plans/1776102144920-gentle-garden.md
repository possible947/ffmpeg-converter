# План достижения паритета Pascal версии с C версией

## Цель
Выявить и реализовать в `fpc/` функциональность, присутствующую в `src/`, чтобы поведение CLI/ядра/GUI Pascal версии максимально совпадало с C версией.

## Что уже установлено (gap-анализ)

### Критические разрывы (P0)
1. **Неполная модель опций в Pascal**
   - В `fpc/converter/converter_types.pas` отсутствуют поля, необходимые для паритета с C:
     - `audio_output_mode`
     - `video_track_path`
     - `hw_device`
     - `hwaccel_enabled`
     - `hevc_vt_bitrate_kbps`
   - Источник-эталон: `src/converter/converter.h`.

2. **Отсутствует mux workflow**
   - В C есть отдельный post-mux pipeline через `mkvmerge` (с валидацией результата и обработкой ошибок).
   - В Pascal аналог отсутствует (нет режима `codec=mux`, нет `--video-track` маршрута).
   - Источники-эталоны: `src/mux/mux.c`, `src/cli/linux/main.c`.

3. **CLI Pascal уже C CLI по возможностям**
   - Нет `--audio-output`, `--video-track`, `mux`, а также части platform-specific кодеков/режимов.
   - Источники: `src/cli/linux/main.c`, `src/cli/macos/main.c`, `fpc/cli/cli_args.pas`.

### Высокий приоритет (P1)
4. **Неполный runtime tool resolution parity**
   - В Pascal есть хороший resolver (`ffmpeg/ffprobe/MP4Box`), но нет C-эквивалентного слоя для `mkvmerge` и Linux runtime probe VAAPI.
   - Источники: `src/platform/linux/runtime_probe.c`, `fpc/common/tool_paths.pas`.

5. **Неполный platform codec parity**
   - C поддерживает `prores_videotoolbox`, `hevc_videotoolbox`, `h264_vaapi`, `hevc_vaapi`, плюс расчет `hevc_vt_bitrate_kbps`.
   - Pascal команда-строитель не покрывает это 1:1.
   - Источники: `src/converter/converter.c`, `fpc/converter/converter_cmd_builder.pas`.

6. **Неполный parity audio output modes**
   - В C есть режимы `pcm`, `fdk_aac_q5`, `fdk_aac_q5_ac3_640` (+ fallback цепочка `aac_at -> libfdk_aac -> aac`).
   - В Pascal отсутствует полная матрица single/dual-audio output и fallback.

### Средний приоритет (P2)
7. **Прогресс анализов (2-pass) в Pascal менее детализирован**
   - Сейчас в Pascal анализ в основном отчитывается финально (100%), без сопоставимого live-прогресса как в C.

8. **GUI parity**
   - В C GUI есть mux/audio-output workflow.
   - В Pascal GUI отсутствуют соответствующие поля/потоки (при наличии отдельного Apple M4V flow).

9. **Тесты parity coverage неполные**
   - Нет достаточного покрытия для mux/audio-output/platform codec matrix, чтобы гарантировать поведенческий parity.

## План реализации

### Этап 1 — Подготовка контрактов и обратной совместимости (P0)
**Задача:** выровнять типы и интерфейсы Pascal с C-эталоном.

- Обновить `TConvertOptions` в `fpc/converter/converter_types.pas` до C-паритета по необходимым полям.
- Проверить `packed record` совместимость и влияние на C ABI слой (`fpc/converter/converter_api_c.pas`, `fpc/converter/converter_pas.h`).
- Обновить дефолты (`InitDefaultOptions`) в соответствии с C-поведением там, где это критично.

**Критерий готовности:** Pascal core может принять все поля, требуемые будущими режимами CLI/mux/platform codecs.

**Риск:** средний (ABI/структуры).

---

### Этап 2 — CLI parity по аргументам и валидации (P0)
**Задача:** вывести Pascal CLI на совместимую семантику.

- Расширить `fpc/cli/cli_args.pas`:
  - добавить `--audio-output`
  - добавить `--video-track`
  - добавить `codec=mux`
  - синхронизировать набор кодеков по платформам (минимум до уровня C-матрицы).
- Добавить/обновить валидации зависимостей аргументов:
  - `mux` требует `--video-track`
  - ограничения по количеству входных файлов в mux режиме (как в C).
- Синхронизировать help/usage и ошибки.

**Критерий готовности:** CLI Pascal принимает и валидирует те же ключевые сценарии, что C CLI.

**Риск:** средний.

---

### Этап 3 — Реализация mux pipeline в Pascal (P0)
**Задача:** добавить отсутствующий функциональный блок.

- Создать Pascal unit для mux логики (аналог `src/mux/mux.c`):
  - подготовка временных артефактов
  - вызов `mkvmerge`
  - проверка результата (наличие ожидаемых дорожек)
  - управляемые cleanup/rollback шаги.
- Интегрировать mux в `converter_core` и CLI flow.
- Нормализовать ошибки и сообщения для callback API.

**Критерий готовности:** рабочий end-to-end `codec=mux` в Pascal CLI.

**Риск:** высокий (много внешних зависимостей/edge-cases).

---

### Этап 4 — Runtime probe и resolver parity (P1)
**Задача:** приблизить runtime-поведение к C.

- Расширить `fpc/common/tool_paths.pas`:
  - добавить `mkvmerge`
  - выровнять приоритеты env/bundled/PATH, где это нужно для parity.
- Добавить Linux-specific runtime probe для VAAPI:
  - детект поддерживаемых кодеков
  - выбор default render node.
- Подключить probe-результаты к выбору кодеков и валидации.

**Критерий готовности:** Pascal корректно определяет доступные инструменты/аппаратные режимы, как C.

**Риск:** высокий (platform-specific runtime).

---

### Этап 5 — Command builder parity (platform codecs + audio output) (P1)
**Задача:** выровнять генерируемые ffmpeg команды.

- Добавить/синхронизировать ветки кодеков:
  - `prores_videotoolbox`
  - `hevc_videotoolbox` (+ расчет bitrate)
  - `h264_vaapi`, `hevc_vaapi`
- Добавить полную матрицу `audio_output_mode`:
  - `pcm`
  - `fdk_aac_q5`
  - `fdk_aac_q5_ac3_640`
  - fallback chain `aac_at -> libfdk_aac -> aac`.
- Выровнять фильтры/маппинг аудио/видео и поведение dual-audio.

**Критерий готовности:** команды Pascal семантически совпадают с C по ключевым режимам.

**Риск:** средний-высокий.

---

### Этап 6 — Прогресс/GUI parity (P2)
**Задача:** довести UX-поведение.

- Улучшить realtime progress в `converter_analysis.pas` до уровня C-подхода.
- Добавить в LCL GUI поля/режимы для `audio-output`, `video-track`, `mux` (без ломки текущего UX).
- Проверить корректность thread-safe обновлений UI.

**Критерий готовности:** сопоставимый пользовательский сценарий в GUI/analysis progress.

**Риск:** средний.

---

### Этап 7 — Тестовый контур parity (P2)
**Задача:** формализовать и зафиксировать parity тестами.

- Расширить тесты в `fpc/test/`:
  - CLI mode matrix для новых опций/режимов
  - unit tests command builder snapshot-style
  - mux integration tests (happy path + fail paths)
  - resolver precedence tests для `mkvmerge`/VAAPI probe.
- Добавить критерии pass/fail parity относительно C-референса.

**Критерий готовности:** тесты подтверждают отсутствие критичных расхождений поведения.

**Риск:** низкий-средний.

## Критерии приемки (Definition of Done)
- Pascal CLI поддерживает ключевые C-сценарии (`mux`, `audio-output`, `video-track`, platform codecs).
- Pascal core принимает и корректно использует C-паритетные опции.
- Mux pipeline в Pascal воспроизводит C-поведение по результату и ошибкам.
- Runtime tool resolution и platform probe дают сопоставимые решения с C.
- Тестовый набор покрывает новые сценарии и стабилен.

## Ограничения и риски
- Различия внешних ffmpeg-сборок между машинами (энкодеры/флаги).
- Потенциальные ABI-эффекты при расширении `packed record`.
- Platform-specific нестабильность Linux VAAPI probe и доступности render nodes.
- Наличие `mkvmerge`/MP4Box в окружении тестов.

## Практический результат после выполнения плана
Pascal версия перестанет отставать по системным функциям C-ветки (особенно mux и платформенные режимы), а parity станет проверяемым и устойчивым через тесты.
