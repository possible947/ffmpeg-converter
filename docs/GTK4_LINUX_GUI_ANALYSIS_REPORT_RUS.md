# Отчёт о Linux GTK4 GUI  
## ffmpeg‑converter Video Converter — C реализация  

**Дата:** 2025‑01‑XX  
**Область применения:** Linux GTK4 GUI (`src/gui/`)  
**Версия:** 2.5

---

## Исполнительное резюме

Linux‑GTK4 GUI имеет несколько критических проблем, влияющих на стабильность, удобство использования и интеграцию с современными рабочими столами. Три основные проблемы, указанные пользователем (заморозка графики, отсутствие поддержки темы, отсутствие drag‑and‑drop), подтверждены, а также выявлены дополнительные архитектурные и UX‑проблемы во время проверки кода.

## 1. Критические проблемы

### 1.1 Заморозка графической подсистемы при запуске

**Серьёзность:** КРИТИЧЕСКАЯ  
**Местоположение:** `gui_main.c:54‑56`, `platform/linux/runtime_probe.c`

**Проблема:**  
Функция `linux_probe_codec_support()` вызывается синхронно в основном GTK‑треде во время активации приложения **до того, как окно будет показано**:

```c
// gui_main.c:54-56
#if defined(__linux__)
    linux_probe_codec_support(&w->linux_codec_support);
#endif

/* Создаём главное окно и все виджеты */
w->window = create_main_window(app, w);
```

Провёрка выполняет:
- многократные запуск `ffmpeg`/`ffprobe`;
- перечисление устройств GPU (Vulkan, VAAPI);
- проверки файловой системы для включённых бинарных файлов;
- тестирование возможностей кодеков.

**Влияние:**
- Приложение «замерзает» 2‑10+ секунд в зависимости от системы.
- Главный цикл GTK блокируется, UI не рендерится.
- На медленных системах или при множестве GPU это может превысить 30 секунд.
- Пользователи могут принудительно закрыть приложение, думая, что оно зависло.

**Корень проблемы:**  
Тяжёлые операции ввода/вывода и запуск процессов выполняются в основном потоке вместо асинхронного выполнения.

---

### 1.2 Отсутствие поддержки светлой/тёмной темы

**Серьёзность:** ВЫСОКАЯ  
**Местоположение:** `gui_window.c` (целый файл), `gui_main.c`

**Проблема:**  
Приложение не учитывает предпочтения системной светлой/тёмной темы. Все виджеты используют стандартную стилизацию GTK4 без пользовательского CSS или адаптивного теминга.

**Доказательства:**
1. Нет создания `GtkCssProvider` и применения его.
2. Нет вызовов `gtk_style_context_add_provider_for_display()`.
3. Нет обнаружения темы через `g_settings_bind()` или `gtk_settings_get_for_screen()`.
4. Жёстко закодированные цвета/стили (не существует, но стандартный GTK может не совпадать с пользовательскими настройками).
5. Нет файла `gtk4.css` или адаптивной стилизации.

**Влияние:**
- Плохая интеграция с окружением рабочего стола (GNOME, KDE и др.).
- Несогласованность внешнего вида с системной темой.
- Проблемы доступности для пользователей, использующих контрастные темы.
- Нет возможности пользователю настроить внешний вид.

---

### 1.3 Отсутствие drag‑and‑drop

**Серьёзность:** СРЕДНИЙ  
**Местоположение:** `gui_window.c`

**Проблема:**  
`GtkListBox`, отображающий список файлов, не принимает перетаскиваемые файлы. Пользователь всегда должен нажимать «Add files…» и открывать диалог выбора файла.

**Доказательства:**
1. Нет вызовов `gtk_drag_dest_set()` на `w->file_listbox`.
2. Нет обработчиков сигнала `drag-data-received`.
3. Нет обработчиков сигнала `drag-drop`.
4. Не настроены `GdkDragAction`.

**Влияние:**
- Неэффективный рабочий процесс для продвинутых пользователей.
- Несоответствие современным требованиям настольных приложений.
- Невозможность интеграции с файловыми менеджерами (Nautilus, Dolphin и др.).

## 2. Архитектурные и проектные проблемы

### 2.1 Глобальная переменная состояния (`g_widgets`)

**Серьёзность:** ВЫСОКАЯ  
**Местоположение:** `gui_callbacks.c:45`

```c
static AppWidgets *g_widgets = NULL;
```

**Проблема:**  
Глобальный указатель на структуру `AppWidgets` используется для передачи состояния виджетов в колбэки. Устанавливается в `run_converter()` и очищается в `shutdown_conversion()`.

**Недостатки:**
- Нарушает инкапсуляцию и усложняет тестирование.
- Возможна гонка, если колбэки срабатывают во время выключения.
- Проблема безопасности памяти: доступ после освобождения `AppWidgets`.
- Код не рекурсивен (может существовать только одна инстанция).

**Рекомендация:** использовать правильную передачу контекста через `g_idle_add_full()` и пользовательские данные.

---

### 2.2 Синхронное создание окна с тяжёлой инициализацией

**Серьёзность:** СРЕДНИЙ  
**Местоположение:** `gui_main.c:58‑60`, `gui_window.c:150‑300`

**Проблема:**  
Весь UI создаётся синхронно в `create_main_window()`, включая заполнение комбинаций кодеков из результатов проверки. Если данные некорректны, создание окна может завершиться неудачей.

**Рекомендация:** показать экран загрузки сразу, построить базовую структуру UI, а динамический контент заполнять асинхронно после завершения проверки.

---

### 2.3 Модальный диалог для опций M4V

**Серьёзность:** СРЕДНИЙ  
**Местоположение:** `gui_window.c:560‑620` (`prompt_m4v_options`)

```c
loop = g_main_loop_new(NULL, FALSE);
// ...
g_main_loop_run(loop);
```

**Проблема:**  
Создаётся вложенный главный цикл `GMainLoop`, что не рекомендуется в GTK/GIO. Это блокирует приложение и может привести к deadlock.

**Рекомендация:** использовать асинхронные колбэки или сигнал ответа `GtkDialog`.

---

### 2.4 Неиспользуемый файл Glade

**Серьёзность:** НИЗКАЯ  
**Местоположение:** `src/ffmpeg_convert.glade`

**Проблема:**  
Файл UI в Glade существует, но не используется. Весь интерфейс строится программно.

**Влияние:**
- Удержание двойного определения UI.
- Возможна путаница среди участников проекта.

**Рекомендация:** либо использовать Glade, либо удалить файл.

## 3. Проблемы управления памятью

### 3.1 Хранение пути файла в `GPtrArray`

**Серьёзность:** СРЕДНИЙ  
**Местоположение:** `gui_window.c:430‑440`, `gui_window.c:680‑690`

**Проблема:**  
При добавлении файлов используется `g_strdup(path)` и добавляется в массив. При удалении вызывается `g_ptr_array_remove(w->file_paths, path)`, что сравнивает указатели.

**Недостатки:**
- Удаление может не сработать из‑за несоответствия указателей.
- Потенциальная утечка памяти при неудачном удалении.
- Массив не завершается `NULL`.

**Рекомендация:** использовать `g_ptr_array_remove_index()` или корректно управлять массивом.

---

### 3.2 Отсутствие очистки `output_dir_path` и `video_track_path`

**Серьёзность:** СРЕДНИЙ  
**Местоположение:** `gui_window.h:35‑36`

**Проблема:**  
Структура `AppWidgets` содержит динамически выделенные строки, но они не освобождаются в `shutdown_conversion()` и `on_app_shutdown()`.

**Влияние:**  
Утечка памяти при каждом запуске приложения. При многократных перезапусках накопление утечки.

---

### 3.3 `GPtrArray` не удаляется

**Серьёзность:** СРЕДНИЙ  
**Местоположение:** `gui_window.h:20`

**Проблема:**  
`w->file_paths` создаётся с `g_ptr_array_new_with_free_func()`, но никогда не освобождается.

## 6. Рекомендации и исправления

### 6.1 Исправить заморозку графики (Приоритет: КРИТИЧЕСКИЙ)

**Решение:** переместить probe в фоновый поток, показать загрузочный экран сразу.

```c
static void activate_cb(GtkApplication *app, gpointer user_data)
{
    AppWidgets *w = g_new0(AppWidgets, 1);
    // Инициализация ...

    w->window = create_main_window(app, w);
    gtk_window_present(GTK_WINDOW(w->window));

    gtk_label_set_text(w->status_label, "Initializing…");

    g_thread_new("codec-probe", async_codec_probe, w);
}
```

### 6.2 Добавить поддержку тем (Приоритет: ВЫСОКАЯ)

**Решение:** создать `GtkCssProvider`, определить стили для светлой/тёмной темы и подключить к дисплею.

```c
static void apply_theme(GtkWindow *window)
{
    GtkCssProvider *provider = gtk_css_provider_new();
    GtkSettings *settings = gtk_settings_get_for_display(gdk_display_get_default());
    gboolean is_dark;
    g_object_get(settings, "gtk-application-prefer-dark-theme", &is_dark, NULL);

    const char *css = is_dark ?
        "listbox row { background-color:#2d2d2d; color:#fff; }" :
        "listbox row { background-color:#fff; color:#000; }";

    gtk_css_provider_load_from_data(provider, css, -1);
    gtk_style_context_add_provider_for_display(
        gdk_display_get_default(),
        GTK_STYLE_PROVIDER(provider),
        GTK_STYLE_PROVIDER_PRIORITY_APPLICATION
    );
    g_object_unref(provider);

    g_signal_connect(settings, "notify::gtk-application-prefer-dark-theme",
                     G_CALLBACK(on_theme_changed), window);
}
```

### 6.3 Добавить drag‑and‑drop (Приоритет: СРЕДНИЙ)

**Решение:** настроить `GtkListBox` как цель drag‑and‑drop и обработать принятые URI.

```c
static void setup_drag_drop(GtkWidget *listbox, AppWidgets *w)
{
    GtkTargetList *targets = gtk_target_list_new(NULL, 0);
    gtk_target_list_add_uri_targets(targets, 0);

    gtk_drag_dest_set(listbox, GTK_DEST_DEFAULT_ALL,
                      targets, 1, GDK_ACTION_COPY);
    g_signal_connect(listbox, "drag-data-received",
                     G_CALLBACK(on_drag_data_received), w);
    gtk_target_list_unref(targets);
}
```

### 6.4 Исправить управление памятью (Приоритет: ВЫСОКАЯ)

**Решение:** в `shutdown_conversion()` освобождать все динамические ресурсы, включая строки и массивы.

```c
void shutdown_conversion(AppWidgets *w)
{
    if (!w) return;
    g_mutex_lock(&w->thread_lock);
    w->shutting_down = TRUE;
    // ...
    g_free(w->output_dir_path);
    g_free(w->video_track_path);
    g_ptr_array_unref(w->file_paths);
}
```

### 6.5 Удалить глобальную переменную `g_widgets` (Приоритет: ВЫСОКАЯ)

**Решение:** передавать указатель на `AppWidgets` через пользовательские данные в колбэках, избегая глобального состояния.

### 6.6 Добавить проверку ввода (Приоритет: СРЕДНИЙ)

**Решение:** показать диалог ошибки при попытке запустить конвертацию без файлов или выходного каталога.

                          "Please add at least one file to convert.");

### 6.7 Установить иконку приложения (Приоритет: НИЗКАЯ)

**Решение:** загрузить и установить `GdkPixbuf` как иконку окна.
