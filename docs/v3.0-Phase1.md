# Version 3.0 — Phase 1: Codec/Preset Architecture Refactor

## 1. Goal

Replace the current flat codec list + prores-only `profile` option with a two-level,
data-driven **codec → preset** model. Codec parameters (ffmpeg arguments, container,
pixel format, pipeline) move from hardcoded branches into a JSON preset file, making
it possible to add new codecs and presets without touching C/Pascal sources.

Phase 1 is a **behavior-preserving refactor**: the initial preset file reproduces
the current hardcoded strings byte-for-byte. New presets (quality tiers for VAAPI,
NVENC, etc.) are added in later phases.

---

## 2. Current State (as-is)

### 2.1 ConvertOptions

| Field | Type | Semantics |
|---|---|---|
| `codec[32]` | `char[]` | Flat list mixing modes (`copy`), codecs (`prores`, `prores_ks`) and encoder names (`h264_vaapi`, `hevc_nvenc`, `prores_ks_vulkan`, `hevc_videotoolbox`). ~14 variants across 3 OSes. |
| `profile` | `int` (0–4) | Meaningful **only** for the prores family: `0=none, 1=lt, 2=standard, 3=hq, 4=4444`. Also affects Vulkan pixel format (4444 → `yuv444p10le`). |

### 2.2 Hardcoded encoder parameters

All HW-encoder quality/bitrate strings are hardcoded in three places:

- C: `src/converter/platform/converter_linux.c:264-281`, `converter_windows.c:530-543`, `converter_macos.c:394-417`
- Pascal: `fpc/converter/converter_cmd_builder.pas:114-156`

Strings are duplicated between C and Pascal and kept in sync manually (per AGENTS.md).

### 2.3 Codec detection

Runtime probing already exists and works well:

- One-frame test encodes per encoder (`src/platform/*/runtime_probe.c`, `fpc/platform/*_probe.pas`)
- Cached results drive CLI and GUI codec menus
- VAAPI: per-render-node probe; NVENC/AMF/QSV: one-frame probe; Vulkan: scan `vk:0..7`

### 2.4 Output naming

Extension depends **only on codec**, not on profile — presets will not break naming.

### 2.5 Problems

- Every new codec × parameter combination requires a new codec menu entry.
- `profile` is prores-specific; other codecs have no equivalent parameter selection.
- Adding quality tiers for VAAPI/NVENC/QSV means duplicating codec entries.
- `mux` → `m4v` is a two-step process (mux to mkv, then convert mkv → m4v).

## 3. Target State (to-be)

### 3.1 Codec menu

The codec menu contains all available codecs and special modes:

| Codec | Description |
|---|---|
| `copy` | Stream copy (default mode, audio processing only) |
| `mux` | Multiplexing (to be extended) |
| `prores` | Software ProRes |
| `prores_ks` | Software ProRes (named profiles) |
| `prores_videotoolbox` | HW ProRes via VideoToolbox (macOS) |
| `prores_ks_vulkan` | HW ProRes via Vulkan (Linux/Windows) |
| `h264_vaapi` / `hevc_vaapi` | HW H.264/HEVC via VAAPI (Linux) |
| `h264_nvenc` / `hevc_nvenc` | HW H.264/HEVC via NVENC |
| `h264_amf` / `hevc_amf` | HW H.264/HEVC via AMF |
| `h264_qsv` / `hevc_qsv` | HW H.264/HEVC via QSV |
| `hevc_videotoolbox` | HW HEVC via VideoToolbox (macOS) |

### 3.2 Preset menu

The preset menu is **codec-dependent**. Each codec has its own set of presets:

| Codec | Available Presets |
|---|---|
| `copy` | `default` |
| `prores` | `lt`, `standard`, `hq`, `4444` |
| `prores_ks` | `lt`, `standard`, `hq`, `4444` |
| `prores_videotoolbox` | `lt`, `standard`, `hq`, `4444` |
| `prores_ks_vulkan` | `lt`, `standard`, `hq`, `4444` |
| `h264_vaapi` | `default` |
| `hevc_vaapi` | `default` |
| `h264_nvenc` / `hevc_nvenc` | `default` |
| `h264_amf` / `hevc_amf` | `default` |
| `h264_qsv` / `hevc_qsv` | `default` |
| `hevc_videotoolbox` | `default` |
| `mux` | `mkv`, `mov`, `m4v` |

**No `none` preset** — codecs without extra parameters use `default`.

### 3.3 Preset file

A JSON file describes all presets, grouped by `os → codec → preset → parameters`.

## 4. Preset File Schema

### 4.1 Structure

```json
{
  "version": "1.0",
  "os_name": {
    "codec_name": {
      "preset_name": {
        "ffmpeg_args": "...",
        "container": "mkv|mov|m4v|mp4",
        "pix_fmt": "...",
        "pre_input_args": "...",
        "video_filter": "...",
        "pipeline": "default|m4v_direct",
        "requires": ["encoder_name", "mkvmerge", "mp4box"]
      }
    }
  }
}
```

### 4.2 Example (Linux)

```json
{
  "version": "1.0",
  "linux": {
    "copy": {
      "default": {
        "ffmpeg_args": "-c:v copy",
        "container": "mkv"
      }
    },
    "prores_ks": {
      "lt": {
        "ffmpeg_args": "-c:v prores_ks -profile:v lt",
        "container": "mov"
      },
      "standard": {
        "ffmpeg_args": "-c:v prores_ks -profile:v standard",
        "container": "mov"
      },
      "hq": {
        "ffmpeg_args": "-c:v prores_ks -profile:v hq",
        "container": "mov"
      },
      "4444": {
        "ffmpeg_args": "-c:v prores_ks -profile:v 4444",
        "pix_fmt": "yuv444p10le",
        "container": "mov"
      }
    },
    "h264_vaapi": {
      "default": {
        "ffmpeg_args": "-c:v h264_vaapi -rc_mode auto",
        "pre_input_args": "-vaapi_device {vaapi_device}",
        "video_filter": "format=nv12,hwupload",
        "container": "mkv",
        "requires": ["h264_vaapi"]
      }
    },
    "prores_ks_vulkan": {
      "lt": {
        "ffmpeg_args": "-c:v prores_ks_vulkan -profile:v lt",
        "pre_input_args": "-init_hw_device vulkan=vk:{vk_device} -filter_hw_device vk",
        "video_filter": "format=yuv422p10le,hwupload",
        "container": "mov",
        "requires": ["prores_ks_vulkan"]
      },
      "4444": {
        "ffmpeg_args": "-c:v prores_ks_vulkan -profile:v 4444",
        "pre_input_args": "-init_hw_device vulkan=vk:{vk_device} -filter_hw_device vk",
        "video_filter": "format=yuv444p10le,hwupload",
        "container": "mov",
        "requires": ["prores_ks_vulkan"]
      }
    },
    "mux": {
      "mkv": {
        "ffmpeg_args": "-c:v copy",
        "container": "mkv",
        "requires": ["mkvmerge"]
      },
      "mov": {
        "ffmpeg_args": "-c:v copy",
        "container": "mov"
      },
      "m4v": {
        "ffmpeg_args": "-c:v copy",
        "container": "m4v",
        "pipeline": "m4v_direct",
        "requires": ["mp4box", "libfdk_aac"]
      }
    }
  }
}
```

### 4.3 Placeholders

Runtime-computed values use placeholders in preset strings:

| Placeholder | Replaced with |
|---|---|
| `{vaapi_device}` | VAAPI render node path (auto-detected or `--hw_device`) |
| `{vk_device}` | Vulkan device index (auto-detected or `--vk_device`) |
| `{vt_bitrate}` | Computed HEVC VideoToolbox bitrate (from resolution/fps) |

### 4.4 File location (search order)

1. Next to the executable (bundled `presets.json`)
2. User config directory (optional override)
3. Built-in minimal fallback (copy/prores/prores_ks with `default`/`standard`)

## 5. ConvertOptions Changes

### 5.1 Field replacement

```c
// Before
int  profile;       // 0=none, 1=lt, 2=standard, 3=hq, 4=4444

// After
char preset[32];    // "default", "lt", "standard", "hq", "4444", "mkv", "mov", "m4v"
```

### 5.2 ABI impact

- `converter.h`: `ConvertOptions.profile` → `ConvertOptions.preset[32]`
- Pascal mirror (`fpc/converter/converter_types.pas`): `profile: LongInt` → `preset: array[0..31] of AnsiChar`
- All 8 exported C ABI functions remain unchanged; only the struct layout changes.
- Acceptable for major version 3.0.

## 6. CLI Changes

### 6.1 Argument parsing

| Old | New |
|---|---|
| `--profile/-p <lt\|standard\|hq\|4444>` | `--preset/-p <preset_name>` (value depends on codec) |
| `--profile` accepts only prores values | `--preset` accepts any preset defined for the selected codec |

`--profile` kept as **deprecated alias** for one release (mapped to preset for prores codecs only).

### 6.2 Help text (`--help`)

Add a notice:

```
IMPORTANT: -c/--codec and -p/--preset must form a valid combination.
Use --codecs-list to see available codec/preset pairs for your system.
```

### 6.3 Validation

Before executing, the CLI validates that the selected preset exists for the selected
codec in the preset file. If not → clear error message:

```
Error: preset 'hq' is not available for codec 'h264_vaapi'.
Use --codecs-list to see valid combinations.
```

### 6.4 New parameter: `--codecs-list`

Prints a structured list of all codec/preset combinations available on the current
system (taking probing results into account):

```
Available codec/preset combinations:

  copy:
    default

  prores_ks:
    lt, standard, hq, 4444

  h264_vaapi:
    default

  hevc_vaapi:
    default

  prores_ks_vulkan:
    lt, standard, hq, 4444

  mux:
    mkv, mov, m4v
```

Only codecs whose encoders passed the runtime probe are shown.

### 6.5 Interactive mode

- Codec step: same as current, but `copy` and `mux` are always present.
- Preset step: populated dynamically from the preset file based on the selected codec.
- `mux` codec: preset step offers `mkv`, `mov`, `m4v`.
- `copy` codec: preset step shows `default` (auto-selected, no prompt).
- Codecs with a single preset (e.g. `h264_vaapi` → `default`): auto-selected, no prompt.

## 7. GUI Changes

### 7.1 GTK4 (Linux)

- Codec combo: populated from probe + preset file (same logic as current, but codec list is stable).
- Preset combo: rebuilt when codec changes; items come from `presets.json[linux][codec]`.
- `mux` codec: preset combo shows `mkv/mov/m4v`.
- `copy` codec: preset combo shows `default` (disabled).

### 7.2 Cocoa (macOS)

- Codec popup: currently hardcoded — switch to dynamic population from preset file + probe.
- Preset popup: same dynamic logic as GTK4.
- Unify macOS probing: use `runtime_probe` VT flags instead of unconditional acceptance.

### 7.3 Lazarus (Windows/Linux Pascal)

- Same dynamic preset combo logic as GTK4.
- `mux` + `m4v` preset: triggers direct M4V pipeline.

## 8. Mux + M4V Direct Pipeline

### 8.1 Current behavior (two-step)

1. `mux` → mkvmerge produces `.mkv`
2. User manually runs M4V conversion (mkv → m4v with AAC + AC3 + MP4Box)

### 8.2 New behavior (one-step)

- `codec = mux`, `preset = m4v` → direct M4V pipeline:
  - Stream-copy video to temp `.mp4`
  - AAC via `libfdk_aac -b:a 320k` CBR
  - AC3 (384/448/640 kbps)
  - `MP4Box` mux with M4V brands
  - Optional chapter transfer
- Reuses the existing Apple M4V pipeline (`src/m4v/m4v.c`, `fpc/converter/apple_m4v_creator.pas`).

### 8.3 Requirements

- `MP4Box` must be available (checked at startup).
- `libfdk_aac` must be available (checked via encoder probe).
- If either is missing, `m4v` preset is disabled in the menu.

## 11. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| ABI break (`ConvertOptions` layout change) | Acceptable for major 3.0; document in release notes. |
| Regression in 14+ encoder paths × 3 OSes | Use `--dry-run` to compare old vs new ffmpeg commands; initial preset file is a byte-for-byte copy of current hardcoded strings. |
| Runtime placeholders (`{vt_bitrate}`, `{vaapi_device}`, `{vk_device}`) | Implement a simple placeholder substitution engine; test each placeholder on real hardware. |
| macOS Cocoa GUI ignores probing | Phase 1 unifies probing across all GUIs. |
| Preset file not found / malformed | Built-in minimal fallback + clear error message at startup. |
| Pascal/C divergence | Both read the same `presets.json`; verify with `--dry-run` on both implementations. |

---

## 12. Recommendations

1. **First preset file = byte-for-byte copy of current hardcoded strings.** Phase 1 is a pure structural refactor; no behavior change.
2. **Regression via `--dry-run`**: run old and new builds on identical inputs, diff the generated ffmpeg commands.
3. **Keep codec IDs as encoder names** (`h264_vaapi`, not "h264 + backend selection") — matches existing probing, avoids scope creep.
4. **Preset is a string, not an index**: `char preset[32]` allows named presets (`lt`, `default`, `m4v`).
5. **JSON format** (jansson already vendored in C; Pascal uses hand-written parser or FCL fpjson).
6. **Load all presets, enable by encoder availability**: read the full preset file at startup; enable presets whose codec encoder passed the probe. No per-preset probe (too expensive).
7. **Schema with fallback**: if the preset file is missing or malformed, fall back to a built-in minimal set (copy/prores/prores_ks).
8. **Unify macOS probing**: use `runtime_probe` VT flags instead of unconditional acceptance.
9. **Document the schema** in this file and validate at load time with clear errors.
10. **Both implementations read the same `presets.json`** — single source of truth for codec parameters.
