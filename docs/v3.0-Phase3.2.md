# FFmpeg Converter v3.0 – Phase 3.2
## Mux Core Specification and Policy Cleanup

## Status

Draft Specification

Phase 3.2 is a corrective refactoring phase.

This phase does not introduce a new feature.

Its purpose is to restore the intended Mux architecture, eliminate accumulated policy inconsistencies, and establish one authoritative and testable behavior model for:

- Mux modes
- Audio processing
- Audio track selection
- Container selection
- Add Track integration
- HQ integration
- Chapter preservation
- Subtitle preservation

This document is normative.

Where current behavior conflicts with this document, the behavior defined here takes precedence.

---

# 1. Implementation Principles

## Existing Functionality First

Phase 3.2 is not a feature-development phase.

Phase 3.2 is a corrective refactoring phase.

The objective is:

```text
Preserve working execution.
Correct policy.
Remove ambiguity.
Restore intended behavior.
```

---

## Reuse Before Rewrite

Before creating a new implementation, the existing implementation must be evaluated for reuse.

The following components are considered proven and should be preserved unless a concrete defect is demonstrated:

- Audio Core
- Audio Orchestrator
- Add Track execution
- MKV mux pipeline
- MOV remux pipeline
- HQ integration handoff
- Chapter handling
- Subtitle handling
- Stream-copy execution
- Existing validation logic

Replacement is allowed only when:

```text
The existing implementation cannot satisfy
the Phase 3.2 requirements.
```

Not because a cleaner implementation is possible.

---

## Policy Correction Has Priority Over Replacement

When behavior is incorrect, the implementation must first determine whether the defect originates from:

- policy
- validation
- selection logic
- GUI filtering
- CLI filtering
- mode interpretation

A working execution module must not be replaced merely to compensate for an incorrect policy layer.

---

## Canonical Behavior Comes From Intended Operation

Phase 3.2 must not reproduce existing bugs.

Phase 3.2 must restore the intended operational model of Mux.

---

## Shared Execution Path

Whenever a working execution path already exists, it must be reused.

Example:

```text
HQ
    ->
video_track.path
    ->
Add Track
    ->
Mux
```

must continue to use the normal Add Track and Mux execution path.

HQ-specific mux implementations are prohibited.

---

## Minimize Surface Area of Change

Phase 3.2 should focus on:

- policy
- validation
- selection logic
- GUI exposure
- CLI exposure

Phase 3.2 should avoid unnecessary changes to:

- Audio Core
- Audio Orchestrator
- Add Track execution
- HQ execution
- mux execution internals

unless a demonstrated defect requires such changes.

---

## Preserve Compatibility

Existing valid workflows must remain valid.

Including:

- MKV workflows
- Audio Copy workflows
- Add Track workflows
- HQ workflows
- Stream-copy workflows

---

## Preferred Implementation Strategy

Implementation order:

```text
1. Reuse existing implementation.
2. Correct policy.
3. Correct validation.
4. Correct GUI exposure.
5. Correct CLI exposure.
6. Extend existing execution modules only where required.
7. Rewrite implementation only if all previous options fail.
```

---

# 2. Design Philosophy

Mux is an instrument.

Mux is not a constructor.

The user selects an operation.

The application determines correct behavior.

The application must not require users to assemble valid combinations manually.

The user selects:

- Mux mode
- Audio mode

The application determines:

- Container
- Extension
- Add Track requirements
- Processing path
- Stream mapping
- Post-processing path

Invalid combinations must never be exposed.

---

# 3. Purpose of Mux

The Mux subsystem is responsible for:

- preserving video streams
- processing audio streams
- preserving chapters
- preserving subtitles
- assembling final output containers

Mux does not encode video.

Mux always copies video streams.

Mux may process audio streams.

---

# 4. Global Stream Preservation Rules

These rules apply to all Mux modes.

## Video

Video streams are copied.

Video re-encoding is prohibited.

## Chapters

All chapters must be preserved.

## Subtitles

All subtitle streams must be preserved whenever supported by the target container.

Loss of subtitles is considered a defect unless explicitly required by target container limitations.

## Metadata

Container metadata should be preserved whenever practical.

---

# 5. Audio Processing Rules

## Audio Copy

Purpose:

Preserve source audio untouched.

Behavior:

```text
Copy all source audio tracks.
Perform no audio processing.
Perform no normalization.
Perform no filtering.
Perform no transcoding.
```

Track policy:

```text
All source audio tracks.
```

---

## Processed Audio

Applies to:

```text
pcm
aac
aac + ac3
```

Behavior:

```text
Use first source audio track.
Perform normal audio processing.
Allow normalization.
Allow filtering.
Allow transcoding.
```

Track policy:

```text
First source audio track only.
```

---

# 6. Mux Modes

The Mux subsystem defines four operational modes.

```text
copy
mkv
mov
m4v
```

These are complete operational modes.

They are not merely presets.

They define behavior.

# 12. Selection Model

Mux contains two meaningful levels.

```text
mux
    ->
copy
mkv
mov
m4v
```

Any third level exists only for storage compatibility.

The third level must not control:

- container
- audio policy
- Add Track behavior

Users must not be required to select a third mux level.

---

# 13. Validation Requirements

The application must reject invalid combinations before execution.

Examples:

```text
mov + copy
mov + aac
mov + aac + ac3

m4v + pcm
m4v + copy

m4v + ProRes replacement track
```

Invalid combinations must not be silently corrected.

A validation error must be returned.

---

# 14. Core Invariants

Audio Copy:

```text
Copy all source audio tracks.
```

Processed Audio:

```text
Use first source audio track.
```

Mux Copy:

```text
Video copied from source file.
```

Mux MKV:

```text
Video copied from Add Track source.
```

Mux MOV:

```text
Video copied from Add Track source.
PCM audio only.
```

Mux M4V:

```text
Video copied from Add Track source.
AAC or AAC+AC3 only.
Default AAC+AC3.
```

HQ ProRes:

```text
MOV output.
PCM audio.
```

HQ Non-ProRes:

```text
MKV output.
```

All Modes:

```text
Preserve chapters.
Preserve subtitles.
Preserve video stream.
```
