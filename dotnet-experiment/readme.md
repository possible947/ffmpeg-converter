# Экспериментальный порт FFMpeg-Converter на .NET & C#

Добро пожаловать в экспериментальный порт проекта **FFMpeg-Converter** на платформу **.NET 10** и язык **C#**. 

Этот каталог создан специально для того, чтобы вы могли вживую оценить возможности экосистемы .NET, простоту её изучения, лаконичность и мощь C#, а также увидеть, насколько архитектурно проще и надежнее становится проект при переходе на этот современный стек.

---

## 🗺️ Структура Портированного Приложения

Порт разделен на четыре логических проекта в рамках единого решения (`FfmpegConverter.slnx`):

1. **`FfmpegConverter.Core`** (Класс-библиотека / Class Library):
   * Содержит всю бизнес-логику конвертера, полностью независимую от интерфейса (CLI или GUI).
   * **`Models/`**: Строго типизированные модели данных (`ConvertOptions.cs` — параметры конвертации, `ConverterError.cs` — перечисление ошибок).
   * **`Presets/`**: Динамический загрузчик базы пресетов (`PresetDb.cs`, `SelectionCatalog.cs`). Считывает `presets.json` v3.0 с поддержкой двухслойного каталога `group -> encoder -> preset`, общих групп (`software`, `mux`) и платформенных аппаратных групп (`videotoolbox`, `vaapi`, `nvenc`, `vulkan`, `amf`, `qsv`).
   * **`Probing/`**: Подсистема автодетекции утилит (`ToolDiscovery.cs` — ffmpeg, ffprobe, mkvmerge, MP4Box) и асинхронного параллельного тестирования видеокарт (`HardwareProbe.cs`).
   * **`Engine/`**:
     * `Converter.cs`: Кроссплатформенный асинхронный движок конвертации с поддержкой событий прогресса, стадий, сообщений и отмены.
     * `CommandBuilder.cs`: Построитель аргументов FFmpeg с поддержкой пресетов, 2-проходного аудиоанализа, фильтра deblock и ресемплера SoXR.
     * `InputVideoInfo.cs`: Анализ метаданных входного видеопотока через `ffprobe`.
     * `AppleM4vPipeline.cs`: Выделенный конвейер создания Apple M4V (stream-copy видео, AAC 320k CBR через `libfdk_aac`, AC3 640k, муксинг через `MP4Box`, импорт глав).
     * `MuxPipeline.cs`: Выделенный конвейер подмены видеодорожки с использованием `mkvmerge`.

2. **`FfmpegConverter.Cli`** (Консольное приложение / Console App):
   * Точка входа в программу (`Program.cs`).
   * **`CommandLineParser.cs`**: Полный парсер аргументов командной строки, на 100% соответствующий базовой C-версии (`-c`, `--encoder`, `-p`, `-d/--deblock`, `-a`, `-m`, `-g`, `--video-track`, `--m4v-*`, `--vk_device`, `--hw_device`, `--codecs-list`, `--dry-run`, `-y`, `-o`).
   * **`InteractiveMenu.cs`**: Пошаговый интерактивный мастер настройки при запуске без параметров (17 шагов, навигация `b` - назад, `c` - отмена, `Enter` - значение по умолчанию).
   * **`CliSummary.cs`**: Блок итоговой сводки параметров перед конвертацией в точном формате базовой C-версии.

3. **`FfmpegConverter.Gui`** (Графическое приложение на Avalonia UI):
   * Кроссплатформенный графический интерфейс (`MainWindow.axaml` / `MainWindow.axaml.cs`).
   * Реализован на современной платформе **Avalonia UI** (v12) и поддерживает работу на Linux, Windows и macOS в строгом соответствии с концепцией v3.0 (3 верхние колонки: Video, Audio, Filters).
   * Автоматическая адаптация под **системную тему (Light / Dark)**: светлое и темное оформление окна, панелей, списков и консольного блока.
   * Предоставляет 3-уровневый каскадный выбор каталога `Группа (Codec) -> Энкодер -> Пресет` с динамической фильтрацией доступных аппаратных кодеков.
   * Поддерживает специализированные диалоги Apple M4V (`AppleM4vDialog.axaml`), режим Mux с выбором замещающей видеодорожки, селекторы адаптеров Vulkan/VAAPI, правила Deblock и динамическую привязку жанров для 2-проходной нормализации EBU R128.
   * Поддерживает Drag-and-Drop файлов прямо в окно программы, детальные логи и расчет ETA/FPS в реальном времени.

4. **`FfmpegConverter.Tests`** (Набор модульных тестов / xUnit):
   * 125 автоматизированных тестов, проверяющих парсинг пресетов, построение команд FFmpeg, анализ входных видео, оба выделенных пайплайна (M4V и Mux), парсер командной строки и модель селекторов GUI.

## ⚔️ Сравнительный анализ: С/Pascal vs C# (.NET)

Переход на .NET решает фундаментальные проблемы исходного кода проекта. Ниже приведено прямое сравнение реализации ключевых задач в C/Pascal и C#:

### 1. Работа с памятью и строками
* **Как было в C / Pascal**: 
  Использование фиксированных массивов `char[32]` или `char[1024]` (в структуре `ConvertOptions`), функций `snprintf` / `strncpy` или ручного выделения памяти с риском переполнения буфера или утечек при сложных путях к файлам.
* **Как стало в C#**: 
  Строки являются безопасными ссылочными типами (`string`). Выделение памяти полностью автоматизировано (Garbage Collector). Манипуляции со строками, склеивание путей (`Path.Combine`) и форматирование аргументов (`$"-c:v {opts.Codec}"`) абсолютно безопасны и пишутся в одну строчку.

### 2. Чтение базы данных `presets.json`
* **Как было в C**: 
  Использование библиотеки `jansson`, сложные циклы обхода JSON-дерева, проверка типов каждого узла, ручное освобождение памяти `json_decref()`. Огромный объем шаблонного кода в `preset_loader.c`.
* **Как стало в C#**: 
  Встроенный высокопроизводительный `System.Text.Json`. Чтение и разбор всего файла в структурированные словари (`Dictionary`) выполняется встроенным парсером автоматически:
  ```csharp
  using var doc = JsonDocument.Parse(jsonText);
  // И мы сразу можем обходить дерево объектов через EnumerateObject() или десериализовать в объекты
  ```

### 3. Запуск процессов и асинхронность
* **Как было в C / Pascal**: 
  Использование `popen()` / `pclose()` в C или сложных утилит `process_utils` в Pascal. Чтение вывода блокирует вызывающий поток. Чтобы GUI не зависал при сканировании видеокарт или конвертации, приходилось создавать потоки ОС (`pthread` или `TThread`), что приводило к багам синхронизации и зависаниям GTK4.
* **Как стало в C#**: 
  Мощнейшая поддержка асинхронности на уровне языка (`async` / `await` / `Task`). Процессы запускаются полностью асинхронно, не блокируя UI. Чтение вывода `ffmpeg` происходит в фоновой задаче, обновляя UI через события:
  ```csharp
  using var process = new Process { ... };
  process.Start();
  while (await reader.ReadLineAsync() is { } line) {
      // парсинг строки
  }
  await process.WaitForExitAsync();
  ```

### 4. Параллельное зондирование оборудования (Hardware Probing)
* **Как было в C / Pascal**: 
  Кодеки тестировались строго последовательно один за другим, что занимало много времени при старте приложения (до нескольких секунд).
* **Как стало в C#**: 
  Благодаря TPL (Task Parallel Library), мы можем запустить тесты всех кодеков **одновременно в параллельных задачах** и дождаться их завершения одной командой:
  ```csharp
  await Task.WhenAll(listOfProbeTasks);
  ```
  Это ускоряет запуск программы на многоядерных процессорах в разы!

## 🚀 Как запустить и протестировать "вживую"

Для сборки и запуска вам понадобится установленный .NET SDK (на этом сервере уже установлена версия 10.0).

### 1. Перейдите в папку эксперимента:
```bash
cd dotnet-experiment
```

### 2. Соберите проект:
```bash
dotnet build
```
Вы увидите, что сборка проходит мгновенно, создавая готовые кроссплатформенные двоичные файлы в каталоге `bin/Debug/net10.0/`.

### 3. Выведите встроенную справку (help):
```bash
dotnet run --project FfmpegConverter.Cli/FfmpegConverter.Cli.csproj -- --help
```

### 4. Проверьте парсинг пресетов и автодетекцию (Codecs List):
Эта команда считает ваш реальный `presets.json` из корня проекта, выведет список доступных кодеков и пресетов, а также попробует протестировать аппаратные энкодеры на вашей видеокарте (если `ffmpeg` доступен в системе):
```bash
dotnet run --project FfmpegConverter.Cli/FfmpegConverter.Cli.csproj -- --codecs-list
```

### 5. Запустите симуляцию (Dry-Run) конвертации:
Вы можете указать любой файл (даже несуществующий, если включить `--dry-run`), чтобы посмотреть, как .NET строит параметры запуска `ffmpeg` на основе выбранного кодека и пресета:
```bash
dotnet run --project FfmpegConverter.Cli/FfmpegConverter.Cli.csproj -- -c h264_vaapi -p speed --audio-norm loudness_norm_2pass --audio-mode fdk_aac_320 --dry-run input_file.mp4
```

### 6. Запустите автоматические тесты (Unit Tests):
В решение включен полный набор тестов (125 тестов), проверяющих все компоненты архитектуры:
```bash
dotnet test
```

### 7. Запустите графический интерфейс (GUI) на Avalonia UI:
Вы можете запустить экспериментальный графический интерфейс программы на любой из целевых платформ (Linux, Windows, macOS):
```bash
dotnet run --project FfmpegConverter.Gui/FfmpegConverter.Gui.csproj
```

## 🎨 Графический интерфейс на Avalonia UI

В данном каталоге реализована полноценная тестовая версия интерфейса программы (`FfmpegConverter.Gui`) с использованием современного XAML-фреймворка **Avalonia UI** (v12). 

### Возможности реализованного GUI:
1. **Кроссплатформенность**: Полная поддержка Linux, Windows и macOS.
2. **Управление файлами**: Кнопки добавления, удаления и полной очистки списка входных файлов.
3. **Выбор каталога назначения**: Удобный выбор папки для сохранения результатов.
4. **Динамический каталог**: Автоматическая подгрузка доступных кодеков и пресетов из базы данных `presets.json` в зависимости от текущей ОС.
5. **Аппаратное ускорение**: Встроенный запуск асинхронного фонового сканирования графических процессоров (Vulkan) и доступных аппаратных кодеков с выводом информации прямо на экран.
6. **Опции конвертации**: Наглядный выбор методов нормализации звука, аудио-режима, флагов перезаписи и Dry-Run.
7. **Асинхронный движок**: Процесс конвертации происходит асинхронно в фоновом потоке, не замораживая и не вешая интерфейс программы.
8. **Интерактивные логи и прогресс**: Плавный прогресс-бар, вывод текущей стадии обработки, скорости (FPS) и расчетного времени (ETA) вместе с выводом логов консоли в реальном времени.

### Как это устроено:
* Описание внешнего вид главного окна в XAML-файле (`MainWindow.axaml`):
  * Верстка выполнена с помощью адаптивной сетки `<Grid>` и `<DockPanel>`.
* Логика привязки и событий (`MainWindow.axaml.cs`):
  * Коллекция `ObservableCollection<string> _inputFiles` автоматически синхронизируется с `ListBox` файлов.
  * При старте вызывается кроссплатформенный движок `FfmpegConverter.Core.Engine.Converter`, события которого обновляют интерфейс на главном потоке с помощью `Dispatcher.UIThread.Post(...)`.


### Почему изучать .NET — это просто и перспективно?
* **C# — один из самых элегантных языков в мире**: Он сочетает строгую статическую типизацию, безопасность C++, лаконичность Python (благодаря var, LINQ и pattern matching) и огромную стандартную библиотеку.
* **Avalonia UI — лучшая замена Lazarus и GTK**: Она работает на Windows, Linux, macOS, iOS, Android и даже в браузере (через WebAssembly), используя единый код разметки. Рендеринг через Skia гарантирует, что интерфейс будет выглядеть абсолютно одинаково и работать плавно на любой операционной системе без зависаний.
* **Единый инструментарий**: Больше никаких CMake, Makefiles, компиляторов fpc и Lazarus IDE. Всё, что нужно для работы — это легкий VS Code (или Rider) и CLI-утилита `dotnet`.
